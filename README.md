# Navi Log Analyzer

이슈 로그를 기반으로 소스코드 흐름을 분석하여 이슈 원인 파악을 지원하는 로그 분석 프로그램

## 프로젝트 소개

내비게이션 개발 및 유지보수 과정에서 발생하는 이슈 로그를 보다 효율적으로 분석하기 위해 개발한
로그 분석 프로그램입니다.

기존에는 이슈 로그를 확인한 후 관련 소스코드를 직접 찾아 로그 발생 흐름과 소스코드 로직을
하나씩 대조해가며 파악해야 했습니다. 이 프로젝트는 이 과정을 자동화합니다 — 로그 파일을
업로드하면 계층별(Container / JNI / Java)로 파싱하고, 사전에 추출해 둔 소스코드 딕셔너리와
매칭하여 함수 호출 흐름을 트리 형태로 재구성해 보여줍니다. 여기에 더해, 반복적으로 발생하는
특정 이슈 유형(예: 목적지 설정 여부·IGN On 상태 확인이 필요한 시나리오)은 사전조건 체크리스트로
자동 검증할 수 있도록 확장했습니다.

Batch(소스코드 딕셔너리 구축) → Backend(업로드/파싱/분석 API) → Front(결과 시각화) 세 모듈로
구성된 개인 진행 프로젝트로, 세 영역 모두 직접 설계·구현했습니다.

---

## 아키텍처

| 모듈 | 역할 |
|---|---|
| **Batch** | 소스코드에서 함수/호출 정보를 추출해 MariaDB 딕셔너리 테이블에 적재. 더 이상 존재하지 않는 항목은 자동으로 비활성 처리 |
| **Backend** | 로그 파일 업로드 → 파싱(계층 분류·시스템 로그 캡처) → 딕셔너리 매칭 → 호출 흐름 트리 생성까지의 REST API |
| **Front** | 업로드 → 처리 상태 표시 → 결과 트리 뷰(검색/필터) → 사전조건 체크리스트까지 이어지는 SPA |

세 모듈은 공통 MariaDB를 공유하며, Backend는 JPA/Hibernate로, Batch는 MyBatis로 접근합니다.

---

## 기술 스택

**Backend** — Spring Boot 4.0.7 · Java 21 · Spring Data JPA / Hibernate · MariaDB · springdoc-openapi

**Batch** — Spring Boot 3.3.5 · Java 21 · Spring Batch (Job/Step) · MyBatis · MariaDB

**Front** — React 19 · Vite 8 · Vitest + Testing Library · CSS Modules (라우터/상태관리 라이브러리/UI 킷 없이 최소 구성으로 개발)

## 주요 기능

### 로그 업로드 & 계층 분류
Android logcat 형식의 로그를 정규식으로 파싱하고, 태그를 기준으로 `CONTAINER` / `JNI_LAYER` /
`JAVA_LAYER` 3개 계층으로 자동 분류합니다. 계층에 속하지 않는 라인 중 관리자가 등록한 키워드와
일치하는 항목(예: IGN On/Off)은 System Log로 별도 캡처합니다.

### 소스코드 흐름도 자동 생성
파싱된 각 로그 라인을 소스코드 딕셔너리와 매칭(함수명+라인 → 함수명 → 키워드 순으로 후보를
좁힌 뒤 정밀 매칭)하고, 각 항목의 호출 목록을 이용해 스택 알고리즘으로 부모-자식 관계를 구성해
함수 호출 흐름 트리를 만듭니다.

### 결과 트리 뷰어
함수/파일명 검색(조상 경로 유지), 매핑됨/매핑 안 됨/전체 필터, 레이어별 색상 배지, 전체
펼치기/접기 등으로 방대한 로그에서도 원하는 흐름을 빠르게 찾을 수 있습니다.

### 이슈 사전조건 체크리스트
자주 반복되는 이슈 유형을 config 기반으로 정의해, System Log 데이터를 근거로 사전조건 충족
여부를 자동 판정합니다. 현재 "Return To Map 자동 이동" 시나리오(목적지 설정 여부 + IGN On
상태 확인)가 구현되어 있으며, 새 시나리오는 코드 변경 없이 설정 추가만으로 확장할 수 있는
구조입니다.

## 개발 현황

### 완료
- Batch: 소스코드 기반 로그 데이터 추출 파이프라인 (Reader/Processor/Writer, MyBatis 적재)
- Backend: 업로드 · 파싱(계층 분류 · System Log 캡처) · 분석(흐름도 생성/저장) REST API
- Front: 업로드 → 처리 상태 → 결과 트리 뷰 전체 플로우, 사전조건 체크리스트(Return To Map)

### 진행 중 / 예정
- 업로드 파일 목록 + 저장된 분석 결과 조회 화면 (설계 완료, 구현 예정)
- 사전조건 시나리오 라이브러리 확장
- Backend / Batch 핵심 로직(파싱 · 매칭 · 트리 생성) 테스트 커버리지 확보
- CI/CD 및 배포 환경 정비

## 테스트

- **Front**: Vitest + Testing Library 기반 13개 테스트 파일(컴포넌트 · 유틸 · API 클라이언트 ·
  통합 플로우 전반)
- **Backend / Batch**: 현재는 컨텍스트 로드 확인 수준의 스모크 테스트만 존재하며, 핵심 로직에
  대한 단위/통합 테스트는 다음 개발 단계에서 보강할 예정입니다.
- **실사용 검증**: 실제 내비게이션 장비 덤프 로그로 Return To Map 사전조건 검증 로직의 정확도를
  확인했습니다.

## 실행 방법

각 모듈에 포함된 `.env.example`을 복사해 `.env`를 만들고 로컬 MariaDB 접속 정보를 채운 뒤
실행합니다.
